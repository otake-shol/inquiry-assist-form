# 画面の設計方針

## 立場

快適な問い合わせとは、「問いを作る仕事」を相手が引き取ってくれること。人が持ってくるのは問いではなく状況であり、それを問いに直す作業をこの画面が引き受ける。

AIは門番ではなく伴走者。使えば早く答えが出るが、使わなくても必ず人に届く。判断基準は「件数を減らせるか」ではなく「問い合わせた人が助かったか」。

本人に感じてほしいことは4つ。

- **受け止められた**: うまく書けなくても責められない
- **理解された**: 言いたかったことを、自分より上手に言ってくれた
- **見通しが立った**: 次に何が起きるかが分かる
- **手を離せた**: 同じ説明を繰り返さなくてよい

## 方針

1. **始める負担を軽くする**: 最初に求めるのは、選択肢を押すことだけ。書くより押すほうが軽い。選択肢は本人の言葉で書き、どの質問にも「わからない」を置く。文章で書きたい人のために、文章で書く道を必ず残す。
2. **理解を言葉で返す**: 整形結果は入力フォームではなく「つまり、こういうことですね」という言い直しの文章で見せる。
3. **質問は尋問ではなく会話にする**: 1問ずつ出し、選択肢を押すだけで進む。「わからない」を常に選べる。選んだことや書いたことを、後の質問で聞き直さない。
4. **待ち時間を信頼に変える**: 何を調べているかを順に見せる。
5. **正直である**: 分からないときは分からないと言う。答えは業務の言葉で書き、根拠は求められたら見せる。本人に見せるのは裏づけを取れた内容だけにする。調査で挙がったが根拠を確かめられなかった内容は、注記をつけても本人には見せず、担当者にだけ渡す。
6. **行き止まりを作らない**: どの質問も「わからない」で進め、選択肢に当てはまらなければ文章で書ける。問いを確かめた後は、答えを待たずに人に渡せる。それより前には渡せない（入力が足りないまま渡すと、担当者の聞き返しが増えるだけになる）。渡すときは「同じ説明は不要」と伝える。
7. **終わりを設計する**: 送った後に何が起きるかを示す。
8. **内部の言葉を見せない**: 「0次回答」「種別」「判定」「整形」「起票」「出典」を画面に出さない。

## 画面の形

1枚のページが会話のように下へ伸びる。画面は入れ替えず、済んだやり取りは要約されて上に残る。段階の番号つき表示は置かない。自由なチャットにはしない。文章を書く場面は、補足（任意）と「少し違います」の一言だけ。本人が望めば、最初から文章で書ける。

流れは次のとおり。

1. **入口の質問**: 最初の画面に、1問目「何をしたいですか」と、選択肢のボタンを出す。押すと答えが確定し、次の質問が現れる。聞く順は、種類、システム、機能、詳しい質問（0〜3問）、補足。質問を決めるのは API で、画面は受け取った質問を描くだけにする。
   - 選択肢のボタンの並びの最後に、控えめな「わからない」を置く（補足を除く、すべての質問）。
   - 種類の選択肢には、短い説明（「操作の手順」など）を添える。
   - 文章で答える質問は、入力欄と「次へ」「わからない」。
   - 補足は、入力欄と「次へ」「書かずに進む」。書かずには進めない場合（API の `canSkip` が偽）は、「書かずに進む」を出さず、文言を「状況を一言で教えてください」にする。
   - 答えた質問は「質問 → 答え」の1行になり、押すとその質問に戻れる（それより後の答えは消える）。AI が文章から置いた答えには「（文章から読み取りました）」と添える。
2. **文章で書く道**: 質問の下に、控えめなリンク「文章で書く」を置く。押すと、入力欄（案内文は「うまくまとまっていなくて大丈夫です。起きていること、知りたいことをそのまま書いてください。」）と「送信する」が出る。送ると、書いた文章が吹き出しとして上に残り、文章から読み取れなかった質問だけが続く。URL の `?text=` に文章があれば、この入力欄を開いて文章を入れておく（自動では送信しない）。モックの例文を選んだときも、この入力欄に入れる。
3. **緊急度**: 入口の質問の間、質問の下に「急ぎですか」と、3つの選択（通常、急ぎ、業務が止まっている）を小さく置く。既定は通常。「業務が止まっている」を選ぶと、詳しい質問を省き、入口を終えた時点で担当者に届く。その場合の終わりの文言は「担当者にすぐ届けました。書いていただいた内容をそのまま添えています。」。
4. **言い直し**: 「つまり、こういうことですね。」に続けて言い直しの文章を示し、「合っています」「少し違います」を置く。
   - 「少し違います」: 「どこが違いますか？」の入力欄を出す。一言書いて送ると言い直しを作り直す。入力欄の下に「自分で書き直す」を置き、押すと言い直しの文章を直接編集して確定できる。
   - 作り直しは2回まで。使い切ったら「うまく汲み取れませんでした。書いていただいた内容のまま担当者に送ることもできます。」と示し、「自分で書き直す」と「このまま担当者に送る」を出す。
   - 「前の質問に戻る」で、最後の質問からやり直せる。
5. **調べている間**: 「調べています」の見出しの下に進捗を1行ずつ足す。済んだ行にはチェック、最新の行には動きのある印をつける。
6. **調べた結果**: 本人向けの説明を主に示す。「根拠にした資料」と「担当者向けの詳しい内容」は折りたたんでおく。
   - **手順**（`answer.steps` があるとき）: 説明の文章のすぐ下に、見出し「手順」／ "Steps" と、番号つきの手順を出す。手順ごとに、何をするか（`action`）を本文の大きさで、確かめ方（`check`。あれば）をその下に小さく「確かめ方: …」／ "Check: …" で出す。手順は書かれた内容なので、言語を切り替えても変わらない（`lang` 属性は本人の言語）。担当者の詳細のパネルの「調べた結果」にも、同じ形で出す。
   - 根拠がない場合: 「手元の資料からは答えを見つけられませんでした。」と示し、担当者に送ることを主のボタンにする。
   - 根拠はあるが、問いに答えられていない場合: 「ご質問への答えは、手元の資料では確認できませんでした。」と示し、その下に「関連して分かったこと」として説明を出す。担当者に送ることを主のボタンにする。調べて分かったことがあっても、問いに答えていなければ、答えとして見せない。
   - 使い方を知りたい、仕組みを知りたい: 「解決しました」「まだ解決していません（担当者に送る）」。
   - おかしいかもしれない: 結果の上に「いまの動きを調べました。この内容を添えて担当者に送りました。」と示す。
   - やってほしい（自分でできる手順が見つかった場合）: 「自分でできました」「担当者に頼む」。手順が見つからなかった場合は、結果の上に「調べた内容を添えて、担当者に送りました。」と示す。
   - 変えてほしい: 調べずに、言い直しを確かめた時点で担当者に送る。
7. **終わり**: 結果ごとの文言と、送った場合は「この後どうなるか」の案内（API の `filedGuidance`）。「新しい問い合わせを書く」で最初に戻る。

「答えを待たずに担当者に送る」は、送れるとき（API の `canSendNow` が真）だけ、ページの下部に置く。言い直しを確かめた後の、調べている間と結果の画面にあたる。添える文言は「待たずに人に見てもらいたいときはこちら。」。入口の質問の間は置かない。言い直しの確認の画面にも置かない（作り直しを使い切った場合は、言い直しの部品の中に「このまま担当者に送る」を出すので、下部には重ねて置かない）。AI の失敗で先へ進めなくなった場合は、エラーの表示の中に「担当者に送る」を出す。

## 誰の番か

問い合わせは、いつも誰かの番で止まっている。本人にも担当者にも、「いま誰の番か」「自分は何をすればよいか」が一目で分かるようにする。状態の値は `api-contract.md` の「状態」が正。

### 本人に見せる言葉

本人のページ（`/inquiries/{id}`）の「いまの状況」と、ボードのカードに出す。

| 待っていること | 本人に見せる言葉 |
| --- | --- |
| 入口の質問に答えている | 入力の途中です |
| 問いを確かめている | 問いの確認をお願いします |
| AI が調べている | 調べています |
| 結果を確かめている（AI の答え） | 結果を確かめてください |
| 結果を確かめている（担当者の結果） | 担当者から結果が届いています |
| 担当者が受けている | 担当者が確認しています |
| 担当者から聞き返されている | 担当者から質問が届いています |
| 担当者が、仕様の持ち主に相談している | 担当者が、仕様を決める人に確認しています |

| 終わり方 | 本人に見せる言葉 | 終わりの文言 |
| --- | --- | --- |
| 解決済み | 解決済み | 解決してよかったです。この内容は記録しておきます。 |
| 回答済み | 回答済み | お返事がなかったため、いったん終了しました。解決していなければ、このページから続きを送れます。 |
| 見送り | 見送り | 担当者から、今回は対応を見送るとの連絡がありました。（続けて、担当者が書いた理由） |
| 取り下げ | 取り下げ | この問い合わせは取り下げました。 |

### 引き継いだ理由を本人に伝える

AI が担当者に引き継いだ件では、本人が自分で送っていないので、なぜ担当者に渡ったのかを伝える。「いまの状況」の「担当者が確認しています」のすぐ下に、1文を添える。`handoverReason` で出し分ける。

| `handoverReason` | 日本語 | 英語 |
| --- | --- | --- |
| `NO_ANSWER` | 調べましたが、はっきりした答えが見つかりませんでした。担当者に引き継ぎました。 | I looked into it but couldn't find a clear answer, so I've handed this over to the support team. |
| `TIMEOUT` | 調べるのに時間がかかっているため、担当者に引き継ぎました。調べた内容は、担当者に渡します。 | This is taking a while to look into, so I've handed it over to the support team. What I find will be passed on to them. |
| それ以外 | 添えない | — |

- 理由の1文を添えた場合、その下の案内（担当者に渡した直後の案内）では、「担当者に送りました。」を繰り返さず、添えた内容だけを伝える（「ここまでの内容と調べた結果を添えています。同じ説明をもう一度する必要はありません。」。調べた結果がなければ「ここまでの内容を添えています。…」）。
- AI が答えられなかった件（`NO_ANSWER`）でも、「調べた結果」は従来どおり見せる（根拠がなければ見つからなかった旨、問いに答えていなければ「関連して分かったこと」）。その下に、解決したかを選ぶボタンは出さない（もう担当者の番なので）。本人に、送るかどうかを選ばせない。
- 時間切れ（`TIMEOUT`）の件は、「調べた結果」を出さない（`answer` が `null`）。後から裏で結果が出ても、本人のページには出さない。伝えるのは担当者。
- 調べている間の「答えを待たずに担当者へ送る」は、これまでどおり出す（時間切れを待たずに、本人が送れる）。

### 本人のページ（担当者に渡した後）

- ページの上部: 左に「問い合わせアシスト」（押すと新しい問い合わせの入力へ）、右に「送った問い合わせ」と利用者の名前。未読の発言があれば「送った問い合わせ」に件数の印をつける。
- 上から、経過の要約（答えた質問、言い直し、調べた結果）、「いまの状況」（上の表の言葉を1行で）、やり取り。
- **やり取り**: 担当者の発言と自分の追記を、古い順に並べる。担当者の発言は左、自分の追記は右。担当者の発言には、聞き返しか、結果か、見送りの連絡かが分かる小さな見出しをつける（「質問」「結果」「見送りの連絡」）。
- **担当者から聞き返されている**: やり取りの下の入力欄の見出しを「担当者の質問に答える」にする。送ると担当者の番になる。
- **担当者から結果が届いている**: やり取りの下に、「やりたかったことは、進められそうですか。」と、「解決しました」「まだ解決していません」を出す。「まだ解決していません」を押すと、どこが解決していないかを書く欄（任意）と「担当者に送る」が出る。
- **担当者が確認している**: 入力欄の見出しは「追加で伝える」。送っても番は変わらない。
- **終わっている**: 終わりの文言を出す。担当者に渡したことがあり、本人が取り下げたのでなければ、入力欄（見出しは「追加で伝える」。案内文は「送ると、担当者の番で開き直します。」）を残す。
- **取り下げる**: 終わっていない問い合わせのページの最下部に、控えめなリンク「この問い合わせを取り下げる」を置く。押すと、その場に確認（「取り下げますか。取り下げた後は、続きを送れません。」と「取り下げる」「やめる」）が出る。ブラウザの確認の窓は使わない。
- AI の答えを確かめる画面（担当者に渡す前）の言葉も、目的の側に寄せる。調べた結果の下に「やりたかったことは、進められそうですか。」と添え、ボタンは「解決しました」「まだ解決していません（担当者に送る）」のまま。
- 途中でページを閉じても、同じ URL を開けば続きから再開できる。

### 返事がないとき

本人の返事を待っている件は、返事がないまま期間が過ぎると、1度知らせたうえで終わる（`api-contract.md` の「返事がないとき」）。結果を確かめている件は「回答済み」、担当者の聞き返しに答えていない件は「取り下げ」で終わる。どちらで終わるかは `noReply.endsAs` で分かる。

- **本人のページ**: 知らせた後（`noReply.remindedAt` がある間）だけ、結果を確かめる選択肢のすぐ上に知らせを出す。知らせる前は何も出さない（急かさない）。
  - 日本語: 「お返事がないため、{日付}に「回答済み」として終了します。解決したかどうかを、下から選んでください。終了した後も、このページから続きを送れます。」
  - 英語: "There has been no reply, so this inquiry will be closed as “Answered” on {date}. Please choose below whether it was resolved. You can still send a follow-up from this page after it is closed."
  - `{日付}` は `noReply.closesAt` の日付。見る人の言語の書式で、月と日を出す（「12月1日」「December 1」）。
- **「回答済み」で終わった件**: 担当者に渡したことのない件（AI の答えに返事がなかった件）にも、続きを送る欄を出す。送ると担当者に渡る。
- **聞き返しに答えていない件**（`noReply.endsAs` が `WITHDRAWN`）: 知らせた後だけ、「担当者の質問に答える」の入力欄のすぐ上に知らせを出す。
  - 日本語: 「お返事がないため、{日付}に「取り下げ」として終了します。続ける場合は、下から担当者の質問に答えてください。終了した後も、このページから続きを送れます。」
  - 英語: "There has been no reply, so this inquiry will be closed as “Withdrawn” on {date}. To continue, please answer the support team's question below. You can still send a follow-up from this page after it is closed."
- **時間で「取り下げ」になった件**（`ending` が `WITHDRAWN` で `closedBy` が `TIME`）: 終わりの文言を「お返事がなかったため、取り下げとして終了しました。続ける場合は、このページから送れます。」／ "This inquiry was closed as withdrawn because there was no reply. You can continue by sending a message from this page." にし、続きを送る欄を出す（本人が自分で取り下げた件には出さない）。
- **担当者の詳細のパネル（聞き返しの返事を待っている件）**: 予定の行の終わり方を「取り下げ」にする（「…返事がなければ、{日付}に「取り下げ」で終わります」／ "…this will be closed as “Withdrawn” on {date}."）。時間で取り下げになった件の履歴は、起こした人が「期間」の「取り下げた」として出る。
- **担当者の詳細のパネル**: 結果を本人が確かめている件に、1行で予定を出す。
  - 知らせる前: 「返事がなければ、{日付}に本人へ知らせます」／ "If there is no reply, the requester will be reminded on {date}."
  - 知らせた後: 「{日付}に本人へ知らせました。返事がなければ、{日付}に「回答済み」で終わります」／ "The requester was reminded on {date}. If there is no reply, this will be closed as “Answered” on {date}."
- **履歴の言葉**（担当者のパネル）: `REMINDED` は「返事がないことを本人に知らせた」／ "Requester reminded (no reply)"、`ANSWERED` は「返事がないまま終わった」／ "Closed after no reply"。起こした人の `TIME` は「期間」／ "Time limit"。

## ボード

担当者の画面（`/operator`）と、本人の「送った問い合わせ」（`/inquiries`）は、課題管理ツールのカンバンと同じ形にする。列は「誰の番か」で分ける。全体でいま何がどこで止まっているかを、一目で見られるようにするため。

### 列

| 画面 | 列（左から） | 入るもの |
| --- | --- | --- |
| 担当者 | 担当者の番 | 番が担当者 |
| 担当者 | 相談中 | 番が仕様の持ち主（決定待ち） |
| 担当者 | 本人の番 | 番が本人（聞き返しへの返事待ち、結果の確かめ待ち） |
| 担当者 | 終わり | 終わっている |
| 本人 | あなたの番 | 番が本人（入力の途中、問いの確認、結果の確かめ、聞き返しへの返事） |
| 本人 | 相手の番 | 番が AI か担当者、または仕様の持ち主（担当者が相談している） |
| 本人 | 終わり | 終わっている |

担当者のボードに出るのは、担当者に渡したことのある問い合わせだけ。

- 列の見出しに、列の名前と件数を出す。カードがない列も出し、「ありません」と薄く示す。
- 列の中は新しい順。ただし、緊急度が「業務が止まっている」のカード、未読のカードの順に、上に寄せる（担当者のボードも、本人のボードも）。
- 列が長くなったら、列の中で縦にスクロールする。列の見出しは見えたままにする。
- 幅が狭いとき（スマホ）は、列を横にスクロールして1列ずつ見る。画面全体は横にはみ出させない。

### カード

- 中身: 言い直しの文章（2行まで。あふれたら省略）、日時、やり取りの件数（1件以上のとき）、未読の印。
- 担当者のカードには加えて、種類、システムと機能、緊急度（通常以外のとき）、区間（分かる、決まる、行われる）。「本人の番」の列では、何を待っているか（「返事待ち」「結果の確かめ待ち」）。「相談中」の列では、相談先の名前。「終わり」の列では、終わり方。
- 本人のカードには、上の「本人に見せる言葉」を添える。
- カードを押すと、その問い合わせを開く。担当者は詳細のパネル、本人は `/inquiries/{id}` のページ。

### 担当者の操作

番を本人に渡すには、本人へのメッセージ（聞き返す内容、または伝える結果）が要る。落としただけで番を渡すと、本人には何も伝わらない。そのため、ドラッグは「操作を始める」合図として扱う。

- **カードを別の列に落とすと、詳細のパネルが開き、その列に対応する入力欄にフォーカスが移る。** 落としただけでは、状態は変わらない。
  - 「担当者の番」から「本人の番」へ: 「本人に送る」の入力欄
  - 「担当者の番」から「相談中」へ: 「相談する」の入力欄
  - 「担当者の番」から「終わり」へ: 「見送る」の入力欄
  - それ以外の動かし方（「本人の番」や「終わり」から動かす）は、受け付けない。番を戻すのは本人の操作であるため。落とせない列は、掴んでいる間、強調しない。
- **ドラッグを使わない方法を必ず用意する。** カードは普通のボタンとして Tab で辿れ、Enter で開ける。開いたパネルの中に、同じ入力欄がある。
- 「未読だけ」の絞り込みは、ボードの上に残す。
- 新しい問い合わせが届いたら、「担当者の番」の列にカードを足し、通知を出す。番が担当者に戻ってきた件も、「担当者の番」の列に動かして未読にする。

### 詳細のパネル（担当者）

カードを押すと、ボードの右側にパネルが開く（URL は `/operator/{id}`。直接開いても同じ状態になる）。ボードは見えたままにし、開いているカードを強調する。パネルは「閉じる」で閉じ、Esc でも閉じる（URL は `/operator` に戻る）。幅が狭いときは、パネルが画面全体を覆う。

パネルの中身は、上から次のとおり。

1. **いまの状態**: 誰の番か、何を待っているか（終わっていれば終わり方）を1行で。種類、システムと機能、緊急度。担当者の番のときは、渡った理由（`handoverReason`）を1行で添える（「渡った理由: …」／ "Why it came to staff: …"）。

   | `handoverReason` | 日本語 | 英語 |
   | --- | --- | --- |
   | `SENT_NOW` | 本人が、答えを待たずに送った | The requester sent it without waiting for an answer |
   | `UNRESOLVED` | 本人が、解決していないと答えた | The requester said it was not resolved |
   | `BLOCKED` | 業務が止まっている | Work is blocked |
   | `ROUTE` | この種類は、担当者が判断する | Staff decide on this type of inquiry |
   | `NO_ANSWER` | AI が答えられなかった | AI could not answer |
   | `TIMEOUT` | AI の調査が、時間内に終わらなかった | AI did not finish looking into it in time |
   | `REOPENED` | 本人が、終わった件に追記した | The requester added to a closed inquiry |
2. **区間**: 「分かる」「決まる」「行われる」の切り替え。担当者の番のときだけ押せる。
3. **置き直す**: 折りたたみ。種類、システム、機能を選び直して「置き直す」。機能の選択肢は、選んだシステムのもの。
4. 本人が書いた文章、入口の質問と答え、言い直し、調べた結果（従来どおり）。「調べた結果」の見出しのすぐ下に、調査の状況（`investigation`）を1行で出す。

   | 状況 | 日本語 | 英語 |
   | --- | --- | --- |
   | `NOT_RUN` | AI は調べていません。 | AI has not looked into this. |
   | `RUNNING` | AI が調べています。終わると、ここに結果が出ます。 | AI is looking into this. The result will appear here when it finishes. |
   | `DONE`、`audience: ASKER` | 本人も、この結果を見ています。 | The requester has seen this result too. |
   | `DONE`、`audience: OPERATOR` | この結果は、本人には見せていません。 | The requester has not been shown this result. |
   | `FAILED` | AI の調査は失敗しました。 | AI's investigation failed. |

   - `unconfirmedQuestion` が `true` のときは、続けて「本人が確かめていない言い直しをもとに調べています。」／ "This is based on a restatement the requester has not confirmed." を出す。
   - 調べ直せるとき（終わっていない、言い直しがある、調べている最中でない）は、ボタンを出す。調べたことがなければ「AI に調べさせる」／ "Have AI look into it"、あれば「調べ直す」／ "Look into it again"。ボタンの下に「番は変わりません。結果は、担当者だけに見えます。」／ "The turn does not change. Only staff can see the result." を添える。
   - 開いているパネルの件に、担当者のストリームの `updated` が届いたら、詳細を取り直す（裏での調査が終わると、開いたままのパネルに結果が出る）。
   **同じ置き場所の先例**（「調べた結果」のすぐ下、「AI の案」の上。`precedents`）: 見出し「同じ置き場所の先例」／ "Precedents for the same place"。先例ごとに、決定の種類、決定の内容、状況、理由、決めた人と日付。機能が違う先例には、その機能の名前を添える。確かめられていない先例には「決めた人が、まだ確かめていません」／ "Not yet confirmed by the person who decided" の印。人が下した決定なので、実線の枠で示す（「仕様の持ち主の決定」と同じ見た目）。なければ「同じ置き場所の先例は、まだありません。」／ "There are no precedents for the same place yet."。節の末尾に、先例の一覧（`/precedents`。この置き場所で絞った状態）へのリンク。

   **AI の案**（「調べた結果」のすぐ下。`advice`）: 事実と見分けがつくように、枠を点線にし、見出しに「案」の印をつける。見出しは「AI の案」／ "AI's suggestion"。見出しのすぐ下に「AI が、上の事実から考えた案です。決めるのは担当者です。」／ "This is a suggestion AI drew from the facts above. The decision is yours." を添える。

   | 状況 | 出すもの |
   | --- | --- |
   | `RUNNING` | 「AI が案を作っています。」／ "AI is preparing a suggestion." |
   | `FAILED` | 「AI の案は作れませんでした。」／ "AI could not prepare a suggestion." |
   | `NOT_RUN`、または `DONE` で案が1つもない | 節を出さない |
   | `DONE` で案がある | 下の2つのうち、あるもの |

   - **判断の案**（見出し「判断の案」／ "Suggested decision"）: 案の文章。続けて、相談が要りそうなら「仕様の持ち主への相談が要りそうです: （理由）」／ "Consulting the spec owner looks necessary: …"、要らなそうなら「相談は要らなそうです。」／ "Consultation does not look necessary."。最後に「基づく事実」／ "Based on" として、事実の文を並べる。先例に基づく案では、「基づく先例」／ "Based on precedents" として、先例の決定の内容と、決めた人、日付を並べる（手順の案も同じ）。
   - **手順の案**（見出し「手順の案」／ "Suggested steps"）: 手順を番号つきで並べる。手順ごとに、対象、操作、確かめ方（「対象」「操作」「確かめ方」／ "Target" "Action" "How to check"）。その下に「元に戻す方法」／ "How to undo"（あれば）と、「基づく事実」。末尾に「実行するのは担当者です。」／ "Staff carry this out." を添える。
   - 案の文章は、書かれたときの言語のまま出す（`lang` 属性は、既定の言語）。

5. **やり取り**: 担当者の発言は右、本人の追記は左。発言の種類（質問、結果、見送りの連絡）を小さく示す。
   **返信の下書き**（6 の入力欄のすぐ上）: 2つの小さなボタン「聞き返しを下書きさせる」「結果を下書きさせる」／ "Draft a question" "Draft a result"。押すと、AI が作った下書きが入力欄に入る。入力欄が空でないときは押せない（書きかけの文章を消さないため。「入力欄が空のときに使えます」／ "Available when the box is empty" を添える）。入力欄に何か書いてから下書きさせたい場合のために、ボタンの上に、1行の入力欄「伝えたいこと（任意）」／ "What you want to say (optional)" を置く（API の `note`）。下書きが入ったら、入力欄の下に「AI の下書きです。確かめて、直してから送ってください。本人の言語（{言語}）で書かれています。」／ "This is an AI draft. Check and edit it before sending. It is written in the requester's language ({language})." を出す（送るか、入力欄を空にすると消える）。AI が直接送ることはない。

6. **本人に送る**（担当者の番のときだけ）: 入力欄1つと、2つのボタン「聞き返す」「結果を伝える」。押したボタンで、本人の番になったときに本人が何を求められるかが決まる。ボタンの下に、違いを1行で添える（「聞き返す: 本人の返事を待ちます」「結果を伝える: 本人が解決したかを確かめます」）。
   **相談する**（担当者の番のときだけ。折りたたみ。6 のすぐ下）: 相談先（既定の相談先を、チェックの入った状態で並べる。外すことも、「ほかの人」の1行の入力欄で名前を足すこともできる）、相談したいこと（入力欄）、ボタン「仕様の持ち主に相談する」／ "Consult the spec owner"。説明を添える: 「相談している間は、仕様の持ち主の番になります。調べた結果や AI の案は、相談先にも見えます。」／ "While you consult, it is the spec owner's turn. They can see what was found and AI's suggestion."。既定の相談先がなく、名前も足していないときは押せない。

   **決定を記録する**（担当者の番のときと、相談している間。折りたたみ）: 見出し「決定を記録する（会議などで決まった場合）」／ "Record a decision (made in a meeting or elsewhere)"。持ち主の画面の「決める」と同じ項目（状況、決定の種類、決定の内容、理由、決めた人）。決めた人は、名前を書く（相談先の名前を候補に出す）。説明を添える: 「決めた人が後から確かめられるように、仕様の持ち主の画面に出ます。」／ "It will appear on the spec owner's screen so that the person who decided can confirm it."

   **相談している間**（`awaiting: CONSULTATION`）: 6 と 7 の代わりに、「仕様の持ち主の決定を待っています（相談先: 名前、名前）」／ "Waiting for the spec owner's decision (consulted: …)"、相談した文章、ボタン「相談を取り下げる」／ "Withdraw the consultation" を出す。取り下げると、担当者の番に戻る。

   **仕様の持ち主の決定**（`decisions` があるとき。「AI の案」のすぐ下）: 見出し「仕様の持ち主の決定」／ "Spec owner's decision"。決定ごとに、決定の種類、決定の内容、理由、状況、決めた人と日付。人が下した決定なので、AI の案（点線の枠）とは違う、実線の枠で示す。決定の文章は、書かれたときの言語のまま出す（`lang` 属性）。

7. **見送る**（担当者の番のときだけ。折りたたみ）: 理由の種類（再現しない、既知の制限、対象外、重複、その他）と、理由の文章、「見送りとして終える」。
8. 担当者の番でないときは、6 と 7 の代わりに、誰の番で何を待っているかを示す（「本人の返事を待っています」など）。
9. **状態の履歴**: 折りたたみ。いつ、誰が、何をして、誰の番になったかを、古い順に。相談の出来事は、`CONSULTED`「仕様の持ち主に相談した」／ "Consulted the spec owner"、`DECIDED`「仕様の持ち主が決めた」／ "Spec owner decided"、`CONSULTATION_CANCELED`「相談を取り下げた」／ "Consultation withdrawn"。起こした人の `OWNER` は「仕様の持ち主」／ "Spec owner"。渡った理由の `DECIDED` は「仕様の持ち主が決めた」／ "The spec owner decided"。
10. スキルの実行記録。

担当者は、見送る場合を除いて、問い合わせを終わらせられない。結果を伝えた後、終わらせるのは本人。パネルにも、その旨を「結果を伝える」の説明として示す。

## 仕様の持ち主の画面

仕様の持ち主は、相談を受けて決める人。進み方の途中に立つ人ではないので、画面は「自分の決定を待っている相談」だけを出す（`/owner`）。

- **左: 相談の一覧**。見出しは「決定を待っている相談」／ "Consultations waiting for a decision"。長く待たせている順。カードには、種類、システムと機能、緊急度（通常以外）、相談した文章（2行まで）、相談した人と日時、相談先の名前。なければ「決定を待っている相談は、ありません。」／ "No consultations are waiting for a decision."。一覧の上に「更新」／ "Refresh" のボタン（開いたときにも取得する。即時には届かない）。
- **右: 詳細**（カードを押すと開く。URL は `/owner/{id}`）。上から:
  1. **相談**: 相談した人、日時、相談先、相談した文章。
  2. **材料**: 担当者の詳細のパネルと同じ内容を、読み取り専用で出す（置き場所、本人が書いた文章、入口の質問と答え、言い直し、調べた結果、AI の案、やり取り）。担当者の操作（区間、置き直す、本人に送る、見送る、調べ直す、下書き）は出さない。
  3. **決める**: 状況（入力欄。最初から、言い直しの文章を入れておく。「どんな状況についての決定かを、後から読む人に分かるように書きます」／ "Describe the situation so that later readers understand what this decision is about."）、決定の種類（意図どおり、不具合、受ける、受けない、採用する、見送る、その他）、決定の内容、理由、決めた人（相談先の名前から選ぶ。相談先が1人なら、最初から選んでおく。「ほかの人」で名前を書ける）、ボタン「決定を記録する」／ "Record the decision"。説明を添える: 「決定は先例として残り、次の同じ種類の問い合わせで、担当者と AI が参照します。本人への連絡は、担当者が行います。」／ "The decision is kept as a precedent that staff and AI refer to for similar inquiries. Staff will tell the requester."
- **確かめてほしい先例**（相談の一覧の下）: 担当者が代わりに記録した、確かめられていない先例を並べる。先例ごとに、内容と、「このとおりです」／ "This is correct"（確かめた）、「直す」／ "Edit"（その場で項目を直して保存する）。なければ、この節を出さない。
- 決めると、その相談は一覧から消え、「決定を記録しました。担当者の番に戻りました。」／ "The decision was recorded. It is staff's turn again." と示す。
- 言語の切り替え、開発用の画面の行き来（本人の画面、担当者の画面、仕様の持ち主の画面）は、ほかの画面と同じ。

決定の種類の言葉:

| 値 | 日本語 | 英語 |
| --- | --- | --- |
| `AS_INTENDED` | 意図どおり | As intended |
| `DEFECT` | 不具合 | Defect |
| `ACCEPT` | 受ける | Accept |
| `REJECT` | 受けない | Do not accept |
| `ADOPT` | 採用する | Adopt |
| `DEFER` | 見送る | Not now |
| `OTHER` | その他 | Other |

## 先例の一覧

担当者と仕様の持ち主が、置き場所ごとに先例を見る画面（`/precedents`）。担当者のボードと、仕様の持ち主の画面の上部に、「先例」／ "Precedents" のリンクを置く。

- 上部に絞り込み: システム、機能（選んだシステムのもの）、種類。URL のクエリ（`?systemId=…&functionId=…&type=…`）に持ち、開き直しても、リンクで渡しても同じ絞り込みになる。
- 先例は新しい順。先例ごとに、置き場所（種類、システム、機能）、決定の種類、決定の内容、状況、理由、決めた人と日付、確かめられていない場合の印、元の問い合わせへのリンク（「元の問い合わせを見る」／ "Open the original inquiry"。担当者の詳細 `/operator/{id}`）。
- 先例の文章は、書かれたときの言語のまま出す（`lang` 属性）。置き場所の名前と決定の種類は、見る人の言語。
- なければ「先例は、まだありません。」／ "There are no precedents yet."。
- この画面では、直せない（直すのは、仕様の持ち主の画面の「確かめてほしい先例」から）。

## スキルの実行記録の表示

開発者向け。`GET /api/config` の `trace` が `true` のときだけ、本人のページの最下部と、担当者の詳細の最下部に、折りたたみ「裏側を見る（開発者向け）」を置く。既定は閉じておく。

開くと、流れの順に段を並べる: 受付 → 聞き手 → 言い直し → 調査 → 照合（コード） → 説明 → 助言 → 案の確認（コード） → 下書き → 訳。助言から後ろの4つは、担当者の詳細にだけ出す（本人のページには出さない）。各段に、種類（AI のスキルか、通常のコードか）、実装（モック／手元のモデルとモデルの名前）、所要時間、トークン数、失敗したかを示す。まだ動いていない段は薄く示す。同じスキルが複数回動いた場合（言い直しの作り直しなど）は、回数と合計を示す。

この表示の中に限り、内部の言葉（スキルの名前、モデルの名前）を使ってよい。

## 言語

画面は、日本語と英語で表示できる。どの文章がどの言語で出るかの決まりは、`api-contract.md` の「言語」の節が正。

### 選び方

- 最初の表示は、ブラウザの言語（`navigator.languages` の順）に合わせる。使える言語に当てはまらなければ、既定の言語。
- 画面の上部（本人の画面も、担当者の画面も）に、言語の切り替えを置く。選択肢は、その言語自身の名前で書く（「日本語」「English」）。いま選んでいる言語が分かるようにする（`aria-current`）。
- 選んだ言語は、ブラウザに保存する。次に開いたときは、保存した言語で表示する。
- 使える言語は、`GET /api/config` の `languages` と、画面が文言を持つ言語の両方に含まれるもの。1つしかなければ、切り替えを出さない。
- 切り替えたら、ページの `lang` 属性とタブの題名を変え、表示中のデータ（設定、問い合わせ、一覧）を取得し直す。種類やシステムの名前は API が返すため。
- 切り替えても、入力の途中の文章は消さない。

### 切り替わるものと、切り替わらないもの

- 切り替わる: 画面の固定の文言、種類・緊急度・システム・機能の名前、設定から来た質問と選択肢、日時の書き方。
- 切り替わらない: 本人が書いた文章、AI が書いた言い直しと説明、担当者の発言、根拠の引用。書かれたときの言語のまま出す。
- 切り替わらない文章には、その文章の言語を `lang` 属性で示す（読み上げが正しい言語で行われるようにするため）。AI が書いたものと本人の文章は問い合わせの `language`、根拠の引用は資料の言語（いまの見本の資料はすべて `ja`）。担当者の発言は、言語が分からないので付けない。

### 担当者の画面

- 本人の言語が、担当者の画面の言語と違うときだけ、パネルの「いまの状態」の下に「本人の言語: English」のように示す（言語の名前は、その言語自身の名前）。本人に送る文章を、どの言語で書けばよいかが分かるようにするため。
- 担当者は、訳を頼める（下の「訳（担当者の画面）」）。返信の下書きは、本人の言語で出る。

### 訳（担当者の画面）

本人の言語が、担当者が見ている言語と違うときだけ、パネルの「本人の言語: English」のすぐ横に、ボタン「訳を見る」／ "Show translation" を出す。

- 押すと、本人の言語で書かれた文章（本人が書いた文章、言い直し、本人向けの説明、本人の発言）のそれぞれのすぐ下に、訳を添える。訳には、小さな見出し「訳（AI）」／ "Translation (AI)" をつけ、原文より控えめな見た目にする（左に細い線、少し小さい文字）。`lang` 属性は、訳した先の言語。
- **原文は必ず残す。** 訳は原文に添えるもので、置き換えない。
- 訳を出している間、ボタンは「訳を隠す」／ "Hide translation" になる。押すと訳を隠す。
- 訳を出している間に、本人の新しい発言が届いたら（担当者のストリームの `updated`）、訳を取り直す（増えた分だけが訳される）。
- 画面の言語を切り替えたら、訳は隠す（訳す先が変わるため）。
- 失敗したら、既存のエラーの出し方で出す。原文は、これまでどおり見えている。
- 本人のページには、訳を出さない。
- 担当者から本人への向きは、返信の下書きを使う（下書きは、本人の言語で書かれる）。

### 英語の言葉

英語の文言は、次の対応に揃える。表にない文言は、この対応と下の「言葉づかい」に合わせて訳す。

| --- | --- |
| 問い合わせアシスト | Inquiry Assist |
| 問い合わせ | inquiry |
| 送った問い合わせ | My inquiries |
| 担当者（本人の画面） | the support team |
| 担当者（担当者の画面） | staff |
| 本人（担当者の画面） | requester |
| あなたの番／相手の番／終わり | Your turn／Their turn／Closed |
| 担当者の番／本人の番／終わり | Staff's turn／Requester's turn／Closed |
| 仕様の持ち主 | spec owner |

| 先例 | precedent |

| 区間（受付、分かる、決まる、行われる、終わり） | Stage（Intake、Understand、Decide、Carry out、Closed） |

英語の文体: 短い平叙文で書く。本人の画面では、内部の言葉（phase、turn、ticket、triage、skill など）を使わない。感嘆符と絵文字は使わない。見出しとボタンは、文の先頭だけを大文字にする（Sentence case）。

## 共通

新しい部分が現れたら、そこが見える位置まで滑らかにスクロールし、読み上げ環境にも伝わるようにする（進捗は `aria-live="polite"`）。キーボードだけで最後まで操作できること。動きを減らす設定（`prefers-reduced-motion`）では動きを止める。

## 言葉づかい

| 内部の言葉 | 画面の言葉 |
| --- | --- |
| 種類（5つ） | 使い方を知りたい、仕組みを知りたい、おかしいかもしれない、やってほしい、変えてほしい |
| 緊急度（3つ） | 通常、急ぎ、業務が止まっている |
| 整形結果の確認 | つまり、こういうことですね。 |
| 0次回答 | 調べた結果 |
| 出典 | 根拠にした資料 |
| 技術メモ | 担当者向けの詳しい内容 |
| 分かったこと／見つからなかったこと／次に確認すること | 分かったこと／調べたが見つからなかったこと／次に確認すること |
| 担当者に渡した（直後の案内。担当者の発言がまだない間だけ出す） | 担当者に送りました。ここまでの内容と調べた結果を添えています。同じ説明をもう一度する必要はありません。 |
| 答えを待たずに送った | 担当者に送りました。書いていただいた内容をそのまま添えています。 |
| 業務が止まっている件として送った | 担当者にすぐ届けました。書いていただいた内容をそのまま添えています。 |
| 解決済み | 解決してよかったです。この内容は記録しておきます。 |
| AIを利用できない | いま自動の調査を使えません。担当者に直接送れます。 |
| AIが回答を拒否した | この内容は自動では調べられませんでした。担当者に直接送れます。 |

文体は「です・ます」。本人を主語にした指示（「入力してください」の連続）を避け、こちらが何をするかを伝える（「調べています」「送りました」）。感嘆符と絵文字は使わない。
