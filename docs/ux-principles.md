# 画面の設計方針

## 立場

快適な問い合わせとは、「問いを作る仕事」を相手が引き取ってくれること。人が持ってくるのは問いではなく状況であり、それを問いに直す作業をこの画面が引き受ける。

AIは門番ではなく伴走者。使えば早く答えが出るが、使わなくても必ず人に届く。判断基準は「件数を減らせるか」ではなく「問い合わせた人が助かったか」。

本人に感じてほしいことは4つ。

- **受け止められた**: うまく書けなくても責められない
- **理解された**: 言いたかったことを、自分より上手に言ってくれた
- **見通しが立った**: 次に何が起きるかが分かる
- **手を離せた**: 同じ説明を繰り返さなくてよい

## 方針

1. **始める負担を軽くする**: 最初に求めるのは、選択肢を押すことだけ。書くより押すほうが軽い。選択肢は本人の言葉で書き、どの質問にも「わからない」を置く。文章で書きたい人のために、文章で書く道を必ず残す。
2. **理解を言葉で返す**: 整形結果は入力フォームではなく「つまり、こういうことですね」という言い直しの文章で見せる。
3. **質問は尋問ではなく会話にする**: 1問ずつ出し、選択肢を押すだけで進む。「わからない」を常に選べる。選んだことや書いたことを、後の質問で聞き直さない。
4. **待ち時間を信頼に変える**: 何を調べているかを順に見せる。
5. **正直である**: 分からないときは分からないと言う。答えは業務の言葉で書き、根拠は求められたら見せる。本人に見せるのは裏づけを取れた内容だけにする。調査で挙がったが根拠を確かめられなかった内容は、注記をつけても本人には見せず、担当者にだけ渡す。
6. **行き止まりを作らない**: どの質問も「わからない」で進め、選択肢に当てはまらなければ文章で書ける。問いを確かめた後は、答えを待たずに人に渡せる。それより前には渡せない（入力が足りないまま渡すと、担当者の聞き返しが増えるだけになる）。渡すときは「同じ説明は不要」と伝える。
7. **終わりを設計する**: 送った後に何が起きるかを示す。
8. **内部の言葉を見せない**: 「0次回答」「種別」「判定」「整形」「起票」「出典」を画面に出さない。

## 画面の形

1枚のページが会話のように下へ伸びる。画面は入れ替えず、済んだやり取りは要約されて上に残る。段階の番号つき表示は置かない。自由なチャットにはしない。文章を書く場面は、補足（任意）と「少し違います」の一言だけ。本人が望めば、最初から文章で書ける。

流れは次のとおり。

1. **入口の質問**: 最初の画面に、1問目「何をしたいですか」と、選択肢のボタンを出す。押すと答えが確定し、次の質問が現れる。聞く順は、種類、システム、機能、詳しい質問（0〜3問）、補足。質問を決めるのは API で、画面は受け取った質問を描くだけにする。
   - 選択肢のボタンの並びの最後に、控えめな「わからない」を置く（補足を除く、すべての質問）。
   - 種類の選択肢には、短い説明（「操作の手順」など）を添える。
   - 文章で答える質問は、入力欄と「次へ」「わからない」。
   - 補足は、入力欄と「次へ」「書かずに進む」。書かずには進めない場合（API の `canSkip` が偽）は、「書かずに進む」を出さず、文言を「状況を一言で教えてください」にする。
   - 答えた質問は「質問 → 答え」の1行になり、押すとその質問に戻れる（それより後の答えは消える）。AI が文章から置いた答えには「（文章から読み取りました）」と添える。
2. **文章で書く道**: 質問の下に、控えめなリンク「文章で書く」を置く。押すと、入力欄（案内文は「うまくまとまっていなくて大丈夫です。起きていること、知りたいことをそのまま書いてください。」）と「送信する」が出る。送ると、書いた文章が吹き出しとして上に残り、文章から読み取れなかった質問だけが続く。URL の `?text=` に文章があれば、この入力欄を開いて文章を入れておく（自動では送信しない）。モックの例文を選んだときも、この入力欄に入れる。
3. **緊急度**: 入口の質問の間、質問の下に「急ぎですか」と、3つの選択（通常、急ぎ、業務が止まっている）を小さく置く。既定は通常。「業務が止まっている」を選ぶと、詳しい質問を省き、入口を終えた時点で担当者に届く。その場合の終わりの文言は「担当者にすぐ届けました。書いていただいた内容をそのまま添えています。」。
4. **言い直し**: 「つまり、こういうことですね。」に続けて言い直しの文章を示し、「合っています」「少し違います」を置く。
   - 「少し違います」: 「どこが違いますか？」の入力欄を出す。一言書いて送ると言い直しを作り直す。入力欄の下に「自分で書き直す」を置き、押すと言い直しの文章を直接編集して確定できる。
   - 作り直しは2回まで。使い切ったら「うまく汲み取れませんでした。書いていただいた内容のまま担当者に送ることもできます。」と示し、「自分で書き直す」と「このまま担当者に送る」を出す。
   - 「前の質問に戻る」で、最後の質問からやり直せる。
5. **調べている間**: 「調べています」の見出しの下に進捗を1行ずつ足す。済んだ行にはチェック、最新の行には動きのある印をつける。
6. **調べた結果**: 本人向けの説明を主に示す。「根拠にした資料」と「担当者向けの詳しい内容」は折りたたんでおく。
   - 根拠がない場合: 「手元の資料からは答えを見つけられませんでした。」と示し、担当者に送ることを主のボタンにする。
   - 根拠はあるが、問いに答えられていない場合: 「ご質問への答えは、手元の資料では確認できませんでした。」と示し、その下に「関連して分かったこと」として説明を出す。担当者に送ることを主のボタンにする。調べて分かったことがあっても、問いに答えていなければ、答えとして見せない。
   - 使い方を知りたい、仕組みを知りたい: 「解決しました」「まだ解決していません（担当者に送る）」。
   - おかしいかもしれない: 結果の上に「いまの動きを調べました。この内容を添えて担当者に送りました。」と示す。
   - やってほしい（自分でできる手順が見つかった場合）: 「自分でできました」「担当者に頼む」。手順が見つからなかった場合は、結果の上に「調べた内容を添えて、担当者に送りました。」と示す。
   - 変えてほしい: 調べずに、言い直しを確かめた時点で担当者に送る。
7. **終わり**: 結果ごとの文言と、送った場合は「この後どうなるか」の案内（API の `filedGuidance`）。「新しい問い合わせを書く」で最初に戻る。

「答えを待たずに担当者に送る」は、送れるとき（API の `canSendNow` が真）だけ、ページの下部に置く。言い直しを確かめた後の、調べている間と結果の画面にあたる。添える文言は「待たずに人に見てもらいたいときはこちら。」。入口の質問の間は置かない。言い直しの確認の画面にも置かない（作り直しを使い切った場合は、言い直しの部品の中に「このまま担当者に送る」を出すので、下部には重ねて置かない）。AI の失敗で先へ進めなくなった場合は、エラーの表示の中に「担当者に送る」を出す。

## 送った後

送って終わりにしない。本人は、送った問い合わせがいまどうなっているかを、いつでも見に行ける。

- **ページの上部**: 左に「問い合わせアシスト」（押すと新しい問い合わせの入力へ）、右に「送った問い合わせ」と利用者の名前。未読の返信があれば「送った問い合わせ」に件数の印をつける。
- **送った問い合わせのボード**（`/inquiries`）: 状態ごとの列にカードを並べる（下記「ボード」）。本人は状態を変えられないので、カードは動かせない。まだ1件もなければ、列を出さずに「送った問い合わせはまだありません。」と、新しい問い合わせを書くボタン。
- **終わった問い合わせのページ**（`/inquiries/{id}`）: 上から、経過の要約（書いたこと、受け取り、質問と回答、言い直し、調べた結果）、終わりの文言、担当者に送った場合は「いまの状況」とやり取り。
- **いまの状況**: 「担当者の確認を待っています」「担当者が対応しています」「対応が完了しました」のどれかを1行で示す。
- **やり取り**: 担当者の返信と自分の追記を、古い順に並べる。担当者の返信は左、自分の追記は右。下に「追加で伝える」の入力欄と「送る」。返信がまだなければ「担当者からの返信は、ここに表示されます。」と示す。やり取りがある場合、終わりの文言の下には「新しい問い合わせを書く」を置かず、やり取りの最後に「別の問い合わせを書く」を控えめに置く（やり取りが主役の場面で、別件の入口を目立たせない）。
- 途中でページを閉じても、同じ URL を開けば続きから再開できる。

状態の言葉:

| 内部の値 | 一覧での言葉 |
| --- | --- |
| 入力の途中（`CLOSED` 以外） | 途中（続きから再開できます） |
| `SELF_RESOLVED` | 解決済み |
| `FILED` と `OPEN` | 担当者の確認待ち |
| `FILED` と `IN_PROGRESS` | 担当者が対応中 |
| `FILED` と `DONE` | 対応完了 |

## ボード

担当者の画面（`/operator`）と、本人の「送った問い合わせ」（`/inquiries`）は、課題管理ツールのカンバンと同じ形にする。状態ごとの列を横に並べ、問い合わせを1件1枚のカードとして、その状態の列に置く。全体でいま何がどこにあるかを、一目で見られるようにするため。

### 列

| 画面 | 列（左から） | 入るもの |
| --- | --- | --- |
| 担当者 | 未対応 | `handlingStatus` が `OPEN` |
| 担当者 | 対応中 | `IN_PROGRESS` |
| 担当者 | 完了 | `DONE` |
| 本人 | 入力の途中 | `step` が `CLOSED` 以外（続きから再開できる） |
| 本人 | 担当者の確認待ち | `FILED` と `OPEN` |
| 本人 | 担当者が対応中 | `FILED` と `IN_PROGRESS` |
| 本人 | 完了 | `FILED` と `DONE`、`SELF_RESOLVED`、`ABANDONED` |

- 列の見出しに、列の名前と件数を出す。カードがない列も出し、「ありません」と薄く示す。
- 列の中は新しい順。ただし未読のカード（担当者は未読の問い合わせ、本人は未読の返信）を上に寄せる。
- 列が長くなったら、列の中で縦にスクロールする。列の見出しは見えたままにする。
- 幅が狭いとき（スマホ）は、列を横にスクロールして1列ずつ見る。画面全体は横にはみ出させない。

### カード

- 中身: 言い直しの文章（2行まで。あふれたら省略）、日時、やり取りの件数（1件以上のとき）、未読の印。
- 担当者のカードには加えて、種別、対象システム、「今すぐ送る」の印。
- 本人の「完了」の列のカードには、終わり方（対応完了／解決済み／終了）を添える。
- カードを押すと、その問い合わせを開く。担当者は詳細のパネル、本人は `/inquiries/{id}` のページ。

### 担当者の操作

- **カードを別の列へドラッグすると、対応状況が変わる。** 掴んでいる間、落とせる列を強調する。変更はすぐ画面に反映し、API が失敗したら元の列に戻して、その旨を示す。
- **ドラッグを使わない方法を必ず用意する。** キーボードと読み上げ環境のため。詳細のパネルの対応状況の切り替え（未対応／対応中／完了）がこれにあたる。カードは普通のボタンとして Tab で辿れ、Enter で開ける。
- 「未読だけ」の絞り込みは、ボードの上に残す。対応状況で絞るタブは置かない（列がその役目をする）。
- 新しい問い合わせが届いたら、「未対応」の列の先頭にカードを足し、通知を出す。本人の追記が届いたら、そのカードを未読に戻して列の上に寄せる。

### 詳細のパネル（担当者）

カードを押すと、ボードの右側にパネルが開く（URL は `/operator/{id}`。直接開いても同じ状態になる）。ボードは見えたままにし、開いているカードを強調する。パネルは「閉じる」で閉じ、Esc でも閉じる（URL は `/operator` に戻る）。幅が狭いときは、パネルが画面全体を覆う。

パネルの中身は、上から、種別と対象システム、対応状況の切り替え、元の発話、言い直し、追加質問と回答、調べた結果、やり取りと「本人に返信する」の入力欄、スキルの実行記録。担当者の返信は右、本人の追記は左。

## スキルの実行記録の表示

開発者向け。`GET /api/config` の `trace` が `true` のときだけ、本人のページの最下部と、担当者の詳細の最下部に、折りたたみ「裏側を見る（開発者向け）」を置く。既定は閉じておく。

開くと、流れの順に段を並べる: 受付 → 聞き手 → 言い直し → 調査 → 照合（コード） → 説明。各段に、種類（AI のスキルか、通常のコードか）、実装（モック／手元のモデルとモデルの名前）、所要時間、トークン数、失敗したかを示す。まだ動いていない段は薄く示す。同じスキルが複数回動いた場合（言い直しの作り直しなど）は、回数と合計を示す。

この表示の中に限り、内部の言葉（スキルの名前、モデルの名前）を使ってよい。

## 共通

新しい部分が現れたら、そこが見える位置まで滑らかにスクロールし、読み上げ環境にも伝わるようにする（進捗は `aria-live="polite"`）。キーボードだけで最後まで操作できること。動きを減らす設定（`prefers-reduced-motion`）では動きを止める。

## 言葉づかい

| 内部の言葉 | 画面の言葉 |
| --- | --- |
| 種類（5つ） | 使い方を知りたい、仕組みを知りたい、おかしいかもしれない、やってほしい、変えてほしい |
| 緊急度（3つ） | 通常、急ぎ、業務が止まっている |
| 整形結果の確認 | つまり、こういうことですね。 |
| 0次回答 | 調べた結果 |
| 出典 | 根拠にした資料 |
| 技術メモ | 担当者向けの詳しい内容 |
| 分かったこと／見つからなかったこと／次に確認すること | 分かったこと／調べたが見つからなかったこと／次に確認すること |
| 起票した | 担当者に送りました。ここまでの内容と調べた結果を添えています。同じ説明をもう一度する必要はありません。 |
| 答えを待たずに送った | 担当者に送りました。書いていただいた内容をそのまま添えています。 |
| 業務が止まっている件として送った | 担当者にすぐ届けました。書いていただいた内容をそのまま添えています。 |
| 自己解決 | 解決してよかったです。この内容は記録しておきます。 |
| AIを利用できない | いま自動の調査を使えません。担当者に直接送れます。 |
| AIが回答を拒否した | この内容は自動では調べられませんでした。担当者に直接送れます。 |

文体は「です・ます」。本人を主語にした指示（「入力してください」の連続）を避け、こちらが何をするかを伝える（「調べています」「送りました」）。感嘆符と絵文字は使わない。
