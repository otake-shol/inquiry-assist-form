# 画面の設計方針

## 立場

快適な問い合わせとは、「問いを作る仕事」を相手が引き取ってくれること。人が持ってくるのは問いではなく状況であり、それを問いに直す作業をこの画面が引き受ける。

AIは門番ではなく伴走者。使えば早く答えが出るが、使わなくても必ず人に届く。判断基準は「件数を減らせるか」ではなく「問い合わせた人が助かったか」。

本人に感じてほしいことは4つ。

- **受け止められた**: うまく書けなくても責められない
- **理解された**: 言いたかったことを、自分より上手に言ってくれた
- **見通しが立った**: 次に何が起きるかが分かる
- **手を離せた**: 同じ説明を繰り返さなくてよい

## 方針

1. **書き始めの摩擦をなくす**: 分類も件名も求めない。最初に求めるのは自由記述だけ。
2. **理解を言葉で返す**: 整形結果は入力フォームではなく「つまり、こういうことですね」という言い直しの文章で見せる。
3. **質問は尋問ではなく会話にする**: 1問ずつ出し、選択肢を押すだけで進む。「わからない」を常に選べる。
4. **待ち時間を信頼に変える**: 何を調べているかを順に見せる。
5. **正直である**: 分からないときは分からないと言う。答えは業務の言葉で書き、根拠は求められたら見せる。本人に見せるのは裏づけを取れた内容だけにする。調査で挙がったが根拠を確かめられなかった内容は、注記をつけても本人には見せず、担当者にだけ渡す。
6. **行き止まりを作らない**: どの時点からでも人に渡せる。渡すときは「同じ説明は不要」と伝える。
7. **終わりを設計する**: 送った後に何が起きるかを示す。
8. **内部の言葉を見せない**: 「0次回答」「種別」「判定」「整形」「起票」「出典」を画面に出さない。

## 画面の形

1枚のページが会話のように下へ伸びる。画面は入れ替えず、済んだやり取りは要約されて上に残る。段階の番号つき表示は置かない。自由なチャットにはしない。文章を書く場面は、最初の入力と「少し違います」の一言だけ。

流れは次のとおり。

1. **入力**: 自由記述の欄と「送信する」。URL の `?text=` に文章があれば入力欄に入れておく（自動では送信しない）。
2. **受け取りの表示**: 「不具合かもしれない件として受け取りました（変更）」の1行。「変更」を押したときだけ4つの選択肢を出す。
3. **追加質問**: 最初に「2つだけ教えてください」と数を伝え、1問ずつ出す。選択肢つきの質問は、選択肢と「わからない」をボタンで並べ、押すと回答が確定して次の質問が現れる。自由記述の質問は入力欄と「次へ」「わからない」。答えた質問は「質問 → 回答」の1行になり、押すと答え直せる（それより後の回答は消える）。最後の質問に答えると自動で送信する。質問が0個なら何も出さずに先へ進む。
4. **言い直し**: 「つまり、こういうことですね。」に続けて言い直しの文章を示し、「合っています」「少し違います」を置く。
   - 「少し違います」: 「どこが違いますか？」の入力欄を出す。一言書いて送ると言い直しを作り直す。入力欄の下に「自分で書き直す」を置き、押すと言い直しの文章を直接編集して確定できる。
   - 作り直しは2回まで。使い切ったら「うまく汲み取れませんでした。書いていただいた内容のまま担当者に送ることもできます。」と示し、「自分で書き直す」と「このまま担当者に送る」を出す。
   - 「前の質問に戻る」で追加質問をやり直せる。
5. **調べている間**: 「調べています」の見出しの下に進捗を1行ずつ足す。済んだ行にはチェック、最新の行には動きのある印をつける。
6. **調べた結果**: 本人向けの説明を主に示す。「根拠にした資料」と「担当者向けの詳しい内容」は折りたたんでおく。
   - 根拠がない場合: 「手元の資料からは答えを見つけられませんでした。」と示し、担当者に送ることを主のボタンにする。
   - 仕様の確認・相談: 「解決しました」「まだ解決していません（担当者に送る）」。
   - 不具合かもしれない件: 結果の上に「いまの動きを調べました。この内容を添えて担当者に送りました。」と示す。
7. **終わり**: 結果ごとの文言と、送った場合は「この後どうなるか」の案内（API の `filedGuidance`）。「新しい問い合わせを書く」で最初に戻る。

「今すぐ担当者に送る」は、問い合わせの作成後から終わりまで常にページの下部に置く。添える文言は「待たずに人に見てもらいたいときはこちら。」。

新しい部分が現れたら、そこが見える位置まで滑らかにスクロールし、読み上げ環境にも伝わるようにする（進捗は `aria-live="polite"`）。キーボードだけで最後まで操作できること。動きを減らす設定（`prefers-reduced-motion`）では動きを止める。

## 言葉づかい

| 内部の言葉 | 画面の言葉 |
| --- | --- |
| 種別の判定（仕様確認・相談） | 仕様の確認・相談として受け取りました |
| 種別の判定（不具合の疑い） | 不具合かもしれない件として受け取りました |
| 種別の判定（作業依頼） | 作業の依頼として受け取りました |
| 種別の判定（障害） | 障害かもしれない件として受け取りました |
| 種別が null（判定できなかった） | 内容を受け取りました |
| 整形結果の確認 | つまり、こういうことですね。 |
| 0次回答 | 調べた結果 |
| 出典 | 根拠にした資料 |
| 技術メモ | 担当者向けの詳しい内容 |
| 分かったこと／見つからなかったこと／次に確認すること | 分かったこと／調べたが見つからなかったこと／次に確認すること |
| 起票した | 担当者に送りました。ここまでの内容と調べた結果を添えています。同じ説明をもう一度する必要はありません。 |
| 今すぐ送るで起票した | 担当者に送りました。書いていただいた内容をそのまま添えています。 |
| 自己解決 | 解決してよかったです。この内容は記録しておきます。 |
| 障害の案内 | 障害の連絡は専用の窓口で受け付けています。（続けて API の `incidentGuidance`） |
| AIを利用できない | いま自動の調査を使えません。担当者に直接送れます。 |
| AIが回答を拒否した | この内容は自動では調べられませんでした。担当者に直接送れます。 |

入力欄の案内文は「うまくまとまっていなくて大丈夫です。起きていること、知りたいことをそのまま書いてください。」。

文体は「です・ます」。本人を主語にした指示（「入力してください」の連続）を避け、こちらが何をするかを伝える（「調べています」「送りました」）。感嘆符と絵文字は使わない。
